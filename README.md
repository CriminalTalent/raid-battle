# RAID 레이드 전투 웹앱

링크 하나로 들어와 여럿이 함께 보스 한 마리를 쓰러뜨리는 격자 레이드 웹앱입니다.
명중·회피·크리티컬 다이스, 정산 순서, 스킬·쿨타임·팀 패시브는 기존 전투봇(`battle/`) 코드를 **그대로** 불러와 계산합니다.

- 설치 없이 PC와 모바일 브라우저에서 바로 참여합니다.
- 7×8 격자에 빈칸이 남는 만큼 참여할 수 있습니다(12명까지 확인).
- 보스, 보스 스킬, 러너 스킬, 팀 패시브, 아이템을 관리자 화면에서 만들고 고칩니다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 로비 | `/` | 진행 중인 레이드 목록 |
| 관리자 | `/admin` | 비밀번호 로그인. 러너·크리쳐·보스 스킬·러너 스킬·팀·아이템 편집, 전투 만들기와 시작, 보스 행동 지정, 입력 마감, 전투 종료, 채팅 |
| 참여자 | `/p/개인코드` | 한 사람에 링크 하나. 캐릭터 카드 확인, 준비 완료, 시작 칸 고르기, 행동 제출, 채팅 |
| 관전자 | `/w/전투번호` | 이름을 넣고 입장. 격자, 체력, 타이머, 전투 기록 보기, 응원 버튼(채팅 보내기 없음) |

한 화면에서 바뀐 내용(행동 제출, 보스 행동, 체력 변화)은 다른 화면에 곧바로 반영됩니다.

## 1. 주요 기능

| 기능 | 내용 |
|---|---|
| 대기실 | 참여자가 링크로 들어와 내 캐릭터 카드(스탯, 팀 패시브, 장비, 소지품)를 확인하고 준비 완료. 관리자가 수치를 고치면 카드에 바로 반영 |
| 시작 위치 | 관리자가 전투를 시작하면 참여자가 격자에서 시작 칸을 고름. 마우스 옆 확인창(Yes/No) |
| 행동 선택 | 마우스 옆 창에서 스킬, 대상 순으로 고르고 "사용하시겠습니까?"에서 Yes. 스킬 사거리가 격자에 표시 |
| 보스 표적 | 보스가 노리는 러너 이름을 격자 위에 표시, 보스 방향은 화살표 |
| 발동 알림 | 보스 전조, 러너 스킬 발동, 보스 스킬 발동을 화면 가운데에 잠깐 표시 |
| 전투 기록 | 입장, 준비 완료, 시작 위치, 행동 예정, 주사위, 피해, 회복 |
| 결과 창 | 승리·패배 표시, [확인]과 [전투 기록 보기] |
| 팀과 패시브 | 관리자가 팀을 만들고 팀마다 패시브 2개 지정. 러너는 둘 중 하나 사용 |
| 역할 | 수호 / 공격 / 지원. 카드 표시용이며 계산에는 영향 없음 |
| 아이템·장비 | 회복 아이템은 전투 중 사용, 무기·갑옷·장신구는 착용 시 스탯 보너스 |
| 보상·압수 | 크리쳐마다 승리 보상과 패배 압수 크레딧(참여자 1명당). 크레딧은 마이너스 가능 |
| 체력 유지 | 전투 후 남은 체력이 저장되어 다음 전투의 시작 체력 기본값이 됨 |
| 화면 | 라이트/다크 모드, PC·모바일 |

## 2. 전투 룰

확률 판정은 모두 d100(1~100)을 굴려 확률 이하가 나오면 성공입니다.

### 기본 설정
- 격자: 가로 A~G(7칸) × 세로 1~8(8칸). 보스는 크기만큼 칸을 차지(예: 2x2), 위치를 비우면 D4.
- 러너 스탯: 건강, 최대건강, 내구도(받는 피해 감소), 마법능력(공격·회복 기준), 민첩(회피율), 기술(명중 보정), 행운(크리티컬 확률)
- 보스 스탯: 건강, 내구도, 마법능력, 민첩, 기술, 행운, 명중기본, 회피기본, 크기, 방향, 스킬목록

### 진행 순서
1. 관리자가 참여자, 시작 체력, 크리쳐, 보스 자동 행동 여부를 정해 **전투 만들기** (이미 다른 전투에 있는 러너는 불가)
2. 참여자가 링크로 입장해 캐릭터 카드 확인 후 **준비 완료**
3. 관리자가 **전투 시작** → 준비 라운드: 참여자가 시작 칸 선택 (보스 칸, 다른 러너가 고른 칸 불가)
4. 매 라운드
   1. 보스 행동 공개: 보스 스킬, 전조 문구, 표적 이름 (1라운드는 항상 전체공격)
   2. 행동 제출: 스킬이나 아이템 1개, 제한 5분. 안 내면 그 라운드 행동 상실
   3. 정산: 전원 제출, 5분 경과, 관리자 [입력 마감] 중 먼저 오는 때
   4. 다음 보스 행동: 관리자가 스킬과 대상(또는 칸) 지정, 또는 [보스 자동 행동]
5. 보스 격파 / 참여자 전원 전투불능 / 관리자 [전투 종료] 시 끝

보스 자동 행동은 스킬목록 중 쿨타임이 돌아온 스킬을 무작위로 고르고 직전 라운드 스킬은 피합니다(선택지가 하나뿐이면 연속 사용).

### 정산 순서
지원 → 방어 → 공격 → 보스 행동. 건강 0이 된 러너는 전투불능이 되고, 이후 행동을 요구하지 않습니다.

### 판정
| 항목 | 계산 |
|---|---|
| 명중 (러너) | 60 + 기술 (%) |
| 보스 회피 | 회피기본 + 보스 민첩 (%) |
| 크리티컬 | 행운 (%). 피해·회복량 × 2 |
| 피해 | 마법능력 × 스킬 배율 − 대상 내구도, 최소 0 |
| 명중 (보스) | 명중기본 + 보스 기술 (%) |
| 러너 회피 | 민첩 (%), 스킬 민첩 보너스 포함 |
| 보호막 | 내구도를 뺀 뒤 남은 피해에서 먼저 차감 |

### 사거리와 쿨타임
- 근접: 둘러싼 8칸(대각선 포함, 체비셰프 거리 1)
- 숫자 사거리: 가로 칸 수 + 세로 칸 수(맨해튼 거리). 사거리 2면 마름모 모양
- 쿨타임 N: 쓴 뒤 N라운드를 쉬고 N+2라운드째 다시 사용 (예: 쿨타임 2를 1라운드에 쓰면 4라운드부터). 내부 저장값은 N+1
- 이동: 1칸(가로·세로·대각선), 쿨타임 없음 / 관찰: 행동하지 않고 넘김
- 러너 스킬은 이름이 아니라 "효과"로 계산되므로 이름을 바꾸거나 배율·사거리만 다른 스킬을 만들어도 기존 규칙대로 계산됩니다.
- 보스 스킬 범위에 `주변N` / `전방N` 을 쓰면 보스 위치·방향 기준으로 칸이 정해집니다.

### 팀 패시브 (8종)
| 이름 | 효과 |
|---|---|
| 정면 수호 | 보스 정면 1칸에 서 있으면 내구도 +50% |
| 역경 | 건강이 40% 미만이면 마법능력 +50% |
| 무결 | 이전 라운드에 피해가 없었으면 마법능력 +50% |
| 관망 | 관찰하면 다음 라운드부터 행운 +10, 전투 끝까지 유지 |
| 통찰 | 보스가 상태이상(혼란, 시야차단)이면 마법능력 +50% |
| 변통 | 직전 라운드와 다른 분류의 행동을 하면 기술 +10 |
| 인내 | 이전 라운드에 맞았으면 내구도 +50% |
| 불굴 | 전투 중 1회, 건강이 0 이하가 되는 것을 막고 1로 남김 |

### 아이템
- 회복 아이템: 행동 창에서 아이템과 대상을 고르면 1명 회복. 사거리 제한 없음, 정산 때 소지품에서 1개 차감
- 장비(무기·갑옷·장신구): 러너 메뉴에서 착용하면 전투 스탯에 보너스

### 승패와 보상
- 승리(보스 건강 0): 참여자 전원 크레딧 + 승리 보상
- 패배(전원 전투불능): 참여자 전원 크레딧 − 패배 압수, 모자라면 마이너스
- 관리자 [전투 종료]: 보상·압수 없이 끝
- 전투가 끝난 체력은 러너 정보에 남습니다.

## 3. 사용법

### 관리자: 처음 한 번 준비
1. `/admin` 에서 비밀번호로 로그인 (12시간 유지, 5번 틀리면 10분 잠김)
2. **팀**: 팀 이름, 패시브 1·2
3. **러너**: ID, 표시 이름, 팀, 패시브 선택(1/2), 스탯, 역할, 두상 이미지, 장비, 소지품, 크레딧, 러너 전용 스킬
4. **크리쳐 (보스몹)**: 이름, 크기, 위치, 방향, 스탯, 명중·회피 기본, 스킬목록, 이미지, 승리 보상, 패배 압수
5. **보스 스킬**: 분류, 범위, 쿨타임, 배율, 디버프, 대상 수, 설명, 전조 문구
6. **러너 스킬·아이템**: 필요하면 추가하거나 이름 변경
- 이미지는 [사진 올리기]로 넣습니다(정사각형으로 잘림, 1MB까지).

### 관리자: 전투 진행
1. 전투 진행 탭에서 참여자, 시작 체력, 크리쳐 선택 → [전투 만들기]
2. 참여자 링크와 관전 링크 복사해 전달 (개인 링크는 본인에게만)
3. 준비 완료가 다 차면 [전투 시작]
4. 라운드마다 보스 스킬과 대상(또는 칸) 지정, 또는 [보스 자동 행동]
5. 늦는 사람이 있으면 [입력 마감]
6. 결과 창이 뜨면 끝. 러너 메뉴에서 크레딧과 남은 체력 확인

### 참여자
- 링크를 열고 캐릭터 카드 확인 → [준비 완료]
- 전투가 시작되면 격자에서 시작 칸 선택 → Yes
- 매 라운드 스킬 → 대상 → Yes
- 결과 창의 [전투 기록 보기]로 기록 다시 보기

### 관전자
- 관전 링크를 열고 이름 입력
- 응원 버튼(박수, 힘내!, 버텨!, 멋져요!, 조심!), 2초에 한 번
- 채팅은 볼 수만 있고 보낼 수 없습니다.

## 4. 설치와 배포

### Render (현재 운영 방식)
- 저장소의 `render.yaml` 블루프린트로 만든 Docker 웹 서비스, **무료(free) 플랜**
- Render: New → Blueprint → 이 저장소 선택 → `RAID_ADMIN_PASSWORD` 입력 → 만들기
- `main` 에 수정이 합쳐지면 자동으로 다시 빌드·배포됩니다. 배포 중에는 잠깐 접속이 끊기고 **진행 중인 전투가 사라지므로** 행사가 없는 시간에 반영하세요.
- 무료 플랜 주의
  - 15분 동안 접속이 없으면 잠들고, 다음 접속 때 30초~1분 뒤에 깹니다. 행사 전에 한 번 열어 두세요.
  - 디스크가 없어서 재시작·재배포 때 러너, 크리쳐, 스킬, 크레딧, 올린 이미지가 `app/data/sample.json` 예시 상태로 돌아갑니다.
  - 데이터를 계속 남기려면 `render.yaml` 의 `plan: free` 를 `starter`(유료)로 바꾸고 `disk` 부분의 `#` 을 지우세요.
- 상태 확인: `/api/battles` 가 응답하면 정상(헬스 체크 주소)

### 환경 변수
| 변수 | 뜻 |
|---|---|
| `RAID_ADMIN_PASSWORD` | 관리자 비밀번호. 주면 켤 때마다 이 값으로 맞춤 (관리자 화면에서 바꿔도 재시작하면 이 값으로 돌아감) |
| `RAID_DATA_DIR` | 데이터(raid.json, 이미지) 폴더. Render에서는 `/data` |
| `PORT` | 열 포트. 주면 외부 접속(0.0.0.0)으로 열림. Render가 자동으로 넣음 |
| `RAID_ACTION_SECONDS` | 행동 제한 시간(초). 기본 300 |

### 다른 서버
- Docker: `docker build -t raid .` → `docker run -d -p 80:4567 -e PORT=4567 -e RAID_ADMIN_PASSWORD=비밀번호 -v raid-data:/data raid`
- Ruby: `PORT=4567 RAID_DATA_DIR=/srv/raid RAID_ADMIN_PASSWORD=비밀번호 ruby app/run.rb`

### 내 컴퓨터(Windows)에서 켜기
1. https://rubyinstaller.org/downloads/ 에서 **WITHOUT DEVKIT** 의 `Ruby 3.3.x (x64)` 설치 (전부 기본값)
2. 이 저장소를 **Code → Download ZIP** 으로 받아 압축 풀기
3. **`start.bat`** 더블클릭 → 검은 창에 관리자 비밀번호가 나오고 관리자 페이지가 열림
4. 다른 사람과 같이 하려면: `cloudflared.exe` 를 같은 폴더에 넣고 **`share.bat`** 실행 → 나온 `https://….trycloudflare.com` 주소를 관리자 화면 **공유 주소** 칸에 넣고 "적용" (주소는 켤 때마다 바뀜)
- 비밀번호를 잊으면 끈 상태에서 `app/data/raid.json` 의 `"admin_key"` 값을 바꿔 저장하세요.

## 5. 유지보수

### 폴더 구조
```
start.bat / share.bat   Windows 실행 파일
Dockerfile / render.yaml 서버 배포 설정
app/
  run.rb                실행 시작점 (포트, 관리자 비밀번호)
  server.rb             웹서버, 페이지 주소와 API
  engine.rb             전투 진행, 대기실, 팀 패시브 연결, 보상·압수, 응원, 관리자 로그인
  skill_catalog.rb      러너 스킬 표 → 규칙 코드가 쓰는 형태
  local_sheet.rb        구글 시트 대신 data/raid.json 읽기·쓰기
  public/               admin·play·watch 페이지, raid.js, raid.css
  data/sample.json      처음 켤 때 복사되는 예시 데이터
battle/                 기존 전투봇 규칙 코드 원본 (TH3V151T0R5_B)
scout/                  기존 조사봇 (보관용, TH3V151T0R5_F)
```

### 데이터
- `raid.json`: 러너, 크리쳐, 보스 스킬, 러너 스킬, 팀, 아이템, 크레딧, 관리자 설정
- `img/`: 올린 이미지
- 진행 중인 전투 상태는 메모리에만 있어서 서버가 다시 시작되면 사라집니다.

### 수정할 때 주의
- 판정과 정산은 `battle/` 코드를 그대로 불러오므로, 여기를 고치면 기존 전투봇과 규칙이 달라집니다. 어느 쪽을 바꿀지 먼저 정하세요.
- 반영 후 확인: 관리자 로그인 → 전투 만들기 → 링크 입장 → 준비 완료 → 시작 칸 → 1라운드 정산까지 한 번 돌려 보기
- 용어: 역할은 수호 / 공격 / 지원. 팀 패시브는 화면에 기숙사 이름 대신 패시브 이름으로만 보입니다.

### 문제가 생겼을 때
| 증상 | 확인할 것 |
|---|---|
| 화면이 안 열림 | 잠든 상태일 수 있음. 1분 뒤 새로고침, 계속 안 되면 Render 대시보드 Logs |
| 비밀번호를 잊음 | Render의 `RAID_ADMIN_PASSWORD` 확인 또는 새로 넣고 저장 |
| 데이터가 처음으로 돌아감 | 무료 플랜 재시작. 관리자 화면에서 다시 입력 |
| 참여자 링크가 안 됨 | 전투가 끝났거나 서버 재시작. 새 전투를 만들어 링크 다시 전달 |
| 진행이 멈춤 | 보스 행동 지정 대기인지 확인. 행동 입력 중이면 [입력 마감] |
