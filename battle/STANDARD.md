# RAID 전투 웹앱 기준 문서 (STANDARD)

이 문서는 RAID 웹앱의 **전투 규칙(변경 금지 기준)** 과 **현재 동작 방식**을 정리한 것입니다.
기존 전투봇(TH3V151T0R5_B)의 전투 규칙·주사위·턴 순서를 그대로 쓰고, 마스토돈·구글 시트 대신 웹 화면과 JSON 파일로 돌아갑니다.
규칙을 바꾸려면 이 문서를 먼저 고친 뒤 코드를 고칩니다.

마지막 갱신: 2026-11-26

---

## 1. 구성

| 부분 | 위치 | 하는 일 |
|---|---|---|
| 전투 규칙 | `battle/` | 기존 전투봇의 판정·정산·보스 패턴 코드 (규칙은 손대지 않음) |
| 엔진 | `app/engine.rb` | 전투 생성·대기실·행동 접수·정산 진행, 1초마다 진행 확인 |
| 서버 | `app/server.rb`, `app/run.rb` | Ruby 기본 HTTP 서버. 화면과 API 제공 |
| 저장소 | `app/local_sheet.rb` | 구글 시트 대신 JSON 파일 한 개(`raid.json`)에 표를 저장 |
| 화면 | `app/public/` | 로비, 관리자, 참여자, 관전자 페이지 |

### 주소

- `/` 로비
- `/admin` 관리자 (비밀번호 필요)
- `/p/<토큰>` 참여자: 러너 한 명당 링크 하나
- `/w/<전투ID>` 관전자: 모두 같은 주소, 이름 입력 후 입장

모든 화면은 실시간으로 이어져 있어서 한 곳에서 바뀐 내용이 다른 화면에 바로 반영됩니다.

## 2. 전투 진행 순서

1. **전투 만들기** (관리자): 상대 보스와 참여자를 고르고 시작 HP를 정합니다.
   - 참여 인원 제한은 없습니다. 등록된 러너 수와 격자 빈칸 수까지만 넣을 수 있습니다.
   - 시작 HP 기본값은 **지난 전투에서 남은 체력**입니다.
2. **링크 전달**: 관리자 화면에 러너별 참여 링크와 관전 링크가 나옵니다.
3. **대기실** (러너)
   - 링크를 열면 내 캐릭터 카드(두상, 역할, 건강, 스탯, 팀·패시브, 스킬, 장비, 소지품)가 보입니다.
   - "내 캐릭터 정보를 확인했어요"에 체크해야 **준비 완료**를 누를 수 있습니다.
   - 정보가 틀리면 관리자가 러너 편집에서 고칩니다. 고친 내용은 러너 화면에 바로 반영됩니다.
4. **전투 시작** (관리자): 준비 현황을 보고 누릅니다. 준비 안 된 사람이 있으면 한 번 더 확인합니다.
   - 이 버튼을 누르기 전에는 타이머가 돌지 않고, 위치 입력도 받지 않습니다.
5. **준비 라운드**: 러너가 격자에서 시작 칸을 누르고 "이곳에 서겠습니까?" 창에서 Yes로 확정합니다.
   - 자리를 고르기 전까지 그 러너는 격자에 보이지 않습니다.
6. **라운드 반복**
   - 1라운드 보스 행동은 전체공격으로 고정입니다.
   - 2라운드부터는 관리자가 보스 행동(스킬·대상·범위 칸)을 정합니다. 자동 모드를 켜면 엔진이 정합니다.
   - 러너는 스킬을 누른 뒤 마우스 옆에 차례로 뜨는 창에서 대상, 칸, 확인을 고릅니다.
   - 모두 제출하거나 입력 시간(기본 300초)이 끝나면 정산합니다. 제출하지 않은 사람은 그 턴을 잃습니다.
7. **종료**: 보스 처치(승리) 또는 전원 전투불능(패배)이면 결과 창이 뜹니다.
   - 결과 창에는 승리자, 확인 버튼, 전체 전투 기록 보기가 있습니다.

### 전투 기록에 남는 것

- 입장, 준비 완료·취소, 진행자의 전투 시작
- 시작 위치: `아린 > 시작 위치 D3`
- 행동 예정 (제출 즉시): `애셔 그레이 > 심핵 공격 예정`, `아린 > 이동(C2) 예정`
- 라운드 안내, 판정·정산 결과, 승리·패배

### 화면 연출 (오버레이)

- 스킬 발동, 보스 스킬 발동, 보스 전조
- **표적**: 보스가 한 명(또는 지정 인원)을 노리면 이름 표시
- 전투 결과

## 3. 전투 규칙 (변경 금지 기준)

### 3-1. 체력

- 체력바는 **현재 체력** 기준입니다.
- 러너 표의 **"최대건강"이 최대 체력의 유일한 출처**입니다. "건강"은 현재 체력이고, 최대 체력에 영향을 주지 않습니다.
- 회복 스킬과 회복 아이템은 **최대 체력을 넘지 않습니다.**
- 전투에서 깎인 체력은 러너 정보에 저장되어 **다음 전투로 이어집니다.** 회복은 관리자가 HP를 고치거나 [러너 전원 체력 회복]으로 합니다.
- 체력이 0인 러너는 회복시켜야 다음 전투에 넣을 수 있습니다.

### 3-2. 표시 이름과 ID

- 전투 기록과 화면에는 ID가 아니라 **표시 이름**이 나옵니다. 표시 이름이 비어 있으면 ID를 씁니다.
- 내부 조회에는 ID, 사람에게 보이는 글에는 표시 이름을 씁니다.

### 3-3. 판정 확률

- 명중률 = 60 + 기술 (%)
- 회피율 = 대상 민첩 × 1% (또는 스킬별 값)
- 크리티컬률 = 행운 × 1% (또는 스킬별 값)
- 모든 확률은 0~100% 범위로 제한합니다.

### 3-4. 희생 (대신 맞기)

- 대상을 정해 자신이 대신 맞습니다.
- 공격자는 명중 판정을 하고, 명중해도 대신 맞는 캐릭터가 회피할 수 있습니다.
- 보스의 모든 공격 유형(기본 반격, 전체·범위·지정 공격)에 똑같이 적용합니다.

### 3-5. 보호 / 방어

- 명중 판정 없이 바로 적용합니다.
- 보호막은 라운드가 지나도 남고, 다시 쓰면 **누적**됩니다.

### 3-6. 강화

- 마법능력을 올리는 버프입니다. **중첩되지 않습니다.** 다시 쓰면 이전 값을 대체합니다.

### 3-7. 고육지책

- 자신의 건강을 소모한 만큼(1:1) 마법능력을 올려 공격합니다.
- 반드시 명중하고, 전투 중 1회만 쓸 수 있습니다.

### 3-8. 격자, 방향, 이동

- 격자는 A~G × 1~8입니다.
- 크리쳐는 상·하·좌·우 중 한 방향을 봅니다. 여러 칸을 차지해도 **위치 칸(머리)이 전방 판정의 기준**입니다. 격자에는 머리 칸 가장자리에 방향 화살표가 표시됩니다.
- 이동은 가로·세로·대각선 **1칸**만 가능하고, 빈칸으로만 갈 수 있습니다.
- 보스 스킬 범위는 `전체`, `주변N`(머리 기준 N칸 안), `전방N`(바라보는 방향으로 N칸)을 쓸 수 있습니다.

### 3-9. 역할 이름

- 역할은 **수호 / 공격 / 지원**으로 부릅니다.

## 4. 관리자가 정하는 것

| 항목 | 내용 |
|---|---|
| 러너 | ID, 표시 이름, 팀과 패시브(둘 중 하나), 건강·최대건강, 내구도, 마법능력, 민첩, 기술, 행운, 역할, 크레딧, 장비, 소지품, 두상 이미지, **전용 스킬** |
| 크리쳐(보스) | 이름, 위치(머리 칸), 크기, 방향, 스탯, 명중·회피 기본값, 고정 스킬, 쓰는 스킬 목록, **승리 보상·패배 압수 크레딧**, 이미지 |
| 보스 스킬 | 관리자가 추가합니다. 범위: 전체 / 주변N / 전방N / 빈칸(무작위 대상) |
| 러너 스킬 | "참여자 표시"가 켜진 스킬은 모두에게 보입니다. 나머지는 러너별 **전용 스킬**로 넣어 줄 수 있습니다. |
| 아이템 | 회복 아이템은 전투 중 사용합니다(쓰면 1개 줄어듦). 장비는 착용하면 스탯 보너스를 줍니다. 상점은 없고, 관리자가 넣어 줍니다. |
| 팀 | 팀 이름과 패시브 두 개를 관리자가 정합니다. |

### 크레딧

- 승리: 참여자 전원에게 보스별 보상 크레딧을 더합니다.
- 패배(전원 전투불능): 보스별 압수 크레딧을 뺍니다. 모자라면 **마이너스**가 됩니다.

### 팀 패시브 (규칙상 4종 × 2개)

| 코드 | 이름 | 효과 |
|---|---|---|
| front_guard | 정면 수호 | 보스 정면 1칸에 서 있으면 내구도 +50% |
| last_stand | 역경 | 건강이 40% 미만이면 마법능력 +50% |
| unscathed | 무결 | 이전 라운드에 피해가 없었으면 마법능력 +50% |
| watchful | 관망 | 관찰(행동 포기)하면 다음 라운드부터 행운 +10 |
| insight | 통찰 | 보스가 상태이상이면 마법능력 +50% |
| adapt | 변통 | 직전 라운드와 다른 분류의 행동을 하면 기술 +10 |
| endure | 인내 | 이전 라운드에 맞았으면 내구도 +50% |
| survive | 불굴 | 전투 중 1회, 건강이 0 이하가 되는 것을 막음 |

## 5. 관전자

- 이름을 입력하고 들어갑니다.
- 채팅은 볼 수만 있고, 응원 버튼(박수 / 힘내! / 버텨! / 멋져요! / 조심!)만 누를 수 있습니다.

## 6. 보안

- 관리자 페이지는 비밀번호로 로그인하고, 로그인은 12시간 유지됩니다.
- 같은 접속지에서 5번 틀리면 10분 동안 잠깁니다.
- 비밀번호는 관리자 설정에서 바꿀 수 있습니다. 서버에서는 환경 변수 `RAID_ADMIN_PASSWORD`가 우선합니다.

## 7. 실행과 배포

### 내 PC (Windows)

- `start.bat` 실행 → 브라우저에서 `http://localhost:4567`
- 다른 사람과 함께 쓰려면 `share.bat`

### 서버 (Render 등)

| 환경 변수 | 뜻 |
|---|---|
| `PORT` | 서버 포트. 주면 외부 접속(0.0.0.0)으로 열림 |
| `RAID_DATA_DIR` | `raid.json`과 이미지 폴더 위치 (Docker 기본 `/data`) |
| `RAID_ADMIN_PASSWORD` | 관리자 비밀번호 |
| `RAID_ACTION_SECONDS` | 행동 입력 시간(초), 기본 300 |

- Render 블루프린트(`render.yaml`)는 무료 플랜 기준입니다.
- 무료 플랜은 디스크가 없어서, 재시작·재배포하면 데이터가 처음 상태로 돌아갑니다. 15분 동안 접속이 없으면 잠들었다가 다음 접속 때 깹니다.
- 데이터를 계속 남기려면 Starter 플랜과 디스크(`/data`)를 씁니다.

## 8. 수정할 때 지킬 것

1. 코드를 먼저 읽고 확인한 뒤에만 "고쳤다"고 적습니다.
2. `battle/`의 전투 규칙 코드는 이 문서의 3장과 어긋나게 바꾸지 않습니다. 웹앱 동작은 `app/`에서 덮어써서 바꿉니다.
3. 표(러너·크리쳐·아이템·팀) 칸 구조를 바꾸면, 기존 `raid.json`이 그대로 읽히도록 옮기는 코드를 함께 넣습니다.
4. 반영 전에 `ruby -c`로 문법을 확인하고, 실제 화면(관리자·참여자·관전자)으로 한 판을 돌려 봅니다.
5. 규칙이나 흐름이 바뀌면 이 문서도 같이 고칩니다.
